# ConfigPilot v1.0.34

本版本修复 macOS 上「修复中转站 401」写入后 Codex 仍报 `Missing environment variable: \`OPENAI_API_KEY\`` 的问题。

## 变更

- **修复 macOS/Linux 的环境变量认证**：此前「修复中转站 401」在非 Windows 平台只把 key 写进 ConfigPilot 自己的进程环境，进程外启动的 Codex 完全读不到，于是 `config.toml` 里 `env_key = "OPENAI_API_KEY"` 指向一个空变量，Codex 启动即报缺变量。
  - 现在非 Windows 平台会把 key 写入 Codex 启动阶段自己加载的 `$CODEX_HOME/.env`（上游 `arg0::load_dotenv` 用 dotenvy 读取），文件权限收紧为 `0600`，其它变量与注释原样保留。
  - Windows 行为不变，仍写 `HKCU\Environment` 并广播 `WM_SETTINGCHANGE`。
- **读取认证同步 .env**：界面与模型探测读取 key 时，与 Codex 的实际解析一致——`$CODEX_HOME/.env` 优先，其次进程环境；快照新增 `envKeySource` 字段标明 key 来自 `dotenv` 还是 `process`。
- **「恢复初始设置」覆盖 .env**：会把 ConfigPilot 新建的 `.env` 删除，或还原到写入前的内容，不会覆盖用户自己的其它变量。
- **提示文案按平台区分**：修复成功后提示 key 的实际落点（Windows 用户环境变量 / `.env` 路径）。

## 升级说明

Windows 与 macOS 都可直接在应用内升级；macOS 会打开官方 Release 页面下载 DMG。

已经配置过中转站、但在 Mac 上见过该报错的用户，升级后重新点一次「修复中转站 401」（或重新保存密钥）即可写入 `.env`，然后 **Cmd+Q 完全退出 Codex** 再打开。

## macOS 首次安装须知

当前 macOS 版本仅支持 Apple Silicon（M 系列芯片），不支持 Intel Mac。

维护者目前没有 Apple Developer Program 会员，因此 DMG 尚未使用 Developer ID 签名和苹果公证。请只从本项目官方 Releases 下载。安装后如被 Gatekeeper 阻止，请执行：

```bash
xattr -dr com.apple.quarantine "/Applications/ConfigPilot.app"
open "/Applications/ConfigPilot.app"
```
